# v1.0 stabilization report — 2026-10-02

This records implementation/review evidence, not a replacement for the version
specification or owner acceptance of the final release. The owner approved
starting v1.0 after the v0.5 baseline assessment. No commits, tags, or remote
publication have been authorized or performed.

## Scope and decisions

- Read the master `plans/plan.md`, every version specification, existing source,
  tests, README/build files, and v0.5 review notes before implementation.
- Retain the existing public Go API, CLI modes, JSON arrays/schemas, quiet tokens,
  address semantics, watch/wait behavior, and exit codes. No new product modes,
  networking protocols, platform process backends, or Go dependencies were added.
- Remove three confirmed-unused internal wrappers (`checker.CheckContext`, CLI
  `render`, and `writeWatch`) after checking all call sites. Root API and live
  test seams are preserved; no architectural refactor was made.
- Resolve conceptual plan examples against actual accepted contracts in
  `docs/contracts.md`. The version format remains `portcheck version <version>`;
  JSON remains an array; watch's established observation/error policy is retained.
- Stabilization fixes two concrete platform/exit-code bugs: wrapped Windows
  Winsock WSAEADDRINUSE is now occupation; Unix broken stdout pipes now return
  documented exit 3 rather than termination by SIGPIPE. Permission/address
  errors are still system failures. SIGPIPE policy belongs only to the executable,
  never the library.
- A source checkout defaults to `1.0.0-dev`; release builds inject their version,
  and versioned Go installations use module build information when no override
  is present. Explicit linker versions take precedence. No timestamp/commit is
  added to ordinary command output.
- Use `1.0.0-rc.1` for local candidate validation. The spec's final `1.0.0` version,
  clean release commit, tag, and publication remain gated on explicit owner review.
- Packaging is developer-only Bash tooling on Linux (GNU tar/gzip/zip/checksum
  utilities). This does not authorize application shell commands or Go dependencies.

## Review findings

### API and CLI

The root API is intentionally retained: `Check`, `CheckPorts`, `CheckHost`,
`CheckPortsHost`, `ValidateHost`, `ValidateEndpoint`, `Connect`; two result/status
models, the existing validation sentinels, and `DefaultConnectTimeout`. No public
process/doctor/watch/parser/renderer/build-metadata APIs were introduced.
The documented distinction between error-free bind occupation and an error on
negative connectivity remains explicit. Batch partial results/joined errors and
non-nil context requirements remain unchanged. Package `go doc` output reviewed.

The compatibility suite executes built binaries, not `go run`, preserving actual
nonzero application exits. Existing deterministic watch ownership/transitions,
all-port wait cycles, timeout/cancellation races, process lookup warnings, and
doctor shared-budget tests remain in place.

### Security and resources

- Product source has no `os/exec`, shell invocation, unsafe operations, process
  modification/termination, privilege escalation, application payloads, retries,
  background probes, or arbitrary output file writes. Subprocesses occur only in
  executable tests and developer build/release tooling.
- Port/range expansion remains bounded by 65535; input is validated before
  networking. Host/endpoint validators reject malformed syntax and controls.
  Process metadata is sanitized for terminals and escaped, unchanged, in JSON.
- Successful bind listeners/dial connections close before return; close failures
  remain errors. Watch/wait own and stop a single ticker; derived contexts are
  canceled. Network/process operations cooperate with cancellation between calls.
- `/proc` lookup is read-only, checks listening sockets, reads metadata only for
  visible candidates, rechecks PID/socket identity, and tolerates disappearance/
  permissions. Executable symlinks are read as metadata, not executed/followed to
  read the binary. Malformed tables return errors, not fabricated ownership.
- No new production goroutines/worker pools/caches were added. Blocking OS calls
  cannot universally be interrupted instantly; live observations are non-atomic.
- Release inputs are validated, dirty checkouts/existing output directories are
  refused by default, and `ALLOW_DIRTY=1` marks local candidates unpublishable.
  Archive contents/timestamps/ownership and checksums are controlled; provenance
  records the intended source/toolchain without embedding local paths or dates.

No critical issue was identified in this focused local review after the two fixes.
This is not a guarantee that fuzzing or local review detects every possible bug.

## Platform and release limitations

Only Linux amd64 has native evidence on this machine. Six-target cross-builds
do not establish other platforms' runtime support. Native CI workflow execution,
especially the targeted Windows Winsock regression and macOS behavior, remains
pending remotely. Unix signal tests are skipped on Windows. Linux arm64 remains
build-only until native evidence is recorded. Process inspection remains Linux-only.

GitHub workflows were authored and YAML-parsed but not executed on GitHub here.
Release archives are local dirty-checkout validation artifacts, not distributable
release files. No tag/draft/remote release/commit was created. No Homebrew/AUR/npm
wrappers or post-v1.0 features were added. Developer packaging is deliberately
Linux-only; application targets remain portable.
