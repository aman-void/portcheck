# v0.5 implementation report

These are implementation notes, not amendments to `plans/v0.5.md` and not
acceptance of the implementation. Review decisions belong to the owner.

The two sections below are preserved verbatim from the original implementation

now covers the complete doctor operation (bind, inspection, and dial).

## Implementation contract clarifications

These resolve conceptual examples against existing repository guidance and
define previously unspecified behavior for the v0.5 implementation:

- The authoritative master is `plans/plan.md`, as specified by `AGENTS.md`.
- JSON remains an array in every mode. Connectivity and doctor emit one-element
  arrays rather than the conceptual object examples in sections 16 and 25.
- Doctor uses `processes` (the existing multiple-owner array), not a singular
  `process`. Owners remain PID-sorted; optional metadata/errors are omitted.
- Connectivity records always include nonnegative fractional `duration_ms`;
  unsuccessful operations include diagnostic `error`, including refusal/timeout.
  Doctor's connectivity record has the same schema, including `address`.
- The CLI calls the public root API. Connectivity is a focused root source file
  rather than an additional internal package, reusing host validation without
  circular dependencies. Doctor composition/rendering stays in separate CLI files.
- Public `Connect(ctx, address, timeout)` returns `(ConnectivityResult, error)`;
  all unsuccessful operations retain the same cause in result and return error.
  `ValidateEndpoint` is syntax-only. The default CLI dial timeout is `5s`.
- Connect exits 0 for reachable, 1 for refused/timeout, 2 for invalid input, and
  3 for other failures, including cancellation and connection cleanup failures.
  Deadlines produce timeout; cancellation produces error. A completed dial is
  not reclassified by a later cancellation. Existing watch/wait semantics stay intact.
- Doctor accepts one single port and automatically inspects occupied results.
  `--process` is redundant but accepted. Quiet/ranges/find/watch/wait/connect and
  polling interval combinations are rejected. Doctor's exit follows connectivity
  except that local bind system errors take precedence (3); process warnings
  never alter it. The timeout covers only dialing, not process inspection.
- Doctor reports sequential observations, not an atomic snapshot. A local bind
  failure does not prevent the explicitly requested connectivity observation.
  Wildcards retain OS-defined semantics; literal local hosts are recommended.
- One DialContext operation is performed, with no application retries/payloads.
  Go's ordinary hostname dialing may attempt multiple resolved addresses.

## Review follow-up implementation notes

These notes do not amend the specification or determine review acceptance.

- Known flags can intervene between `--connect` and its endpoint. Success tests
  cover quiet/JSON/timeout flag orderings, including the cases from the review;
  invalid, unknown, missing-value, and conflicting-mode cases remain rejected.
- The owner selected a special default-host shorthand: `--host --quiet 8080`
  quietly checks port 8080 on `127.0.0.1`. This is intentionally specific to
  long `--quiet`; `--host -q 8080` still errors. Help and README document it.
- The owner selected observed-instant reporting: human watch transitions use
  `IN USE  observed since HH:MM:SS`, not a near-zero elapsed duration. Repeated
  polls and process-only changes do not repeat the marker; FREE/ERROR reset it.
  Initial-state, quiet, one-shot/JSON, and doctor output remain unchanged by
  the watch feature. Deterministic injected-clock tests verify the new instants.
- Doctor now shares one finite timeout context across local binding, process
  inspection (including resolution), and dialing. No fresh dial budget is added
  after inspection. A deadline produces an explicit doctor timeout diagnostic,
  without replacing already completed observations. OS-call interruption remains
  cooperative, as documented in README. Tests cover shared/inherited deadlines
  and expiry in both the bind and inspection stages.
- The specification was restored byte-for-byte to HEAD. The two historical
  sections above were moved verbatim; reconstructing the previous specification
  plus these notes reproduces its original SHA-256 digest.
